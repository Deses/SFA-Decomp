# Effects-state and environment-action boundaries

The tail of the former `main/render.c` contains two independent units:

- `main/effects_state.c`: the mode getter/setter and default sequence callback,
  with the shared pool-update marker and mode word.
- `main/envfx.c`: the immediate and ordinary environment-action dispatchers,
  with their private `EnvfxActEntry` layout.

The old `render.c` grouping originated in commit `970cb8a182`, a mechanical
partition of a 283-function placeholder into nine broad address ranges. It was
not evidence that the entire range was one original translation unit.

## Retail layout

In every retail version, the model/packed-data prefix ends at `80008B4C`.
The state routines occupy `80008B4C..80008B74`, followed by the environment
dispatchers at `80008B74..80008DF4`. Function order is unchanged.

The model prefix's private constants, scratch buffer, output pointers, and
root rotations remain with its code. Its interpolation routine calls the two
packed-data helpers immediately preceding the new boundary. The interpolation
constant follows the joint-matrix constants within the same pool, rather than
starting a new eight-byte-aligned pool. None of the four moved functions
references this data.

The model BSS contains a pointer and three shorts: ten bytes, followed by six
bytes of linker alignment. The separately aligned state section contains the
one-byte pool-update marker, three alignment bytes, and four-byte mode. Putting
the state globals into the former combined TU would pack them at offsets 10
and 12, rather than retail's 16 and 20. Separate ordinary sections reproduce
the layout without padding declarations, type inflation, or alignment overrides.

## Independent source correspondence

The Dinosaur Planet reference's `src/segment_13D0.c` independently groups the
same `s16` mode getter/setter, seven-argument default callback returning `-1`,
and byte marker. Its expgfx caller writes the marker as 1/0 around the pool
update and queries the mode using `-1`, just as SFA's expgfx does. Two additional
no-op functions and another word in that older source have no corresponding
claim here.

The following donor `src/envfx.c` contains the same two action dispatchers,
including the action-kind routing and immediate-action field clearing. This
supports a separate environment unit rather than attaching it to the state
globals. The older game's heap allocation and function order are not copied:
SFA retains its retail stack buffers and retail function order.

`effects_state.c` is a descriptive name; `envfx.c` has donor support. Neither
claims a recovered GameCube source filename. Retail source-leak searches found
no direct filename evidence. The existing model prefix is retained without
claiming that its earlier broad grouping has been fully audited.

## Verification

All five versions retain all ten scored functions exactly. The unchanged
joint-matrix assembly body remains in the model prefix. The model unit has
9,386 exact data bytes; the state unit has eight; the environment unit has no
allocated data. All five `ninja all_source` builds and native strict retail
checksums pass with the recovered state linked from source.

Compiler versions and optimization settings are unchanged. The shared marker
declaration moves to the existing mode API header already included by its two
consumers. No consumer source changes are needed. The previous eight-byte
autogenerated BSS unit disappears; only the 24 bytes of documented MusyX/MSL
metadata reporting differences remain unscored.

Regional projection reproduces all three complete split blocks in each
secondary version. The independent retail operand audit confirms both state
globals and all six paired r13-relative references per secondary version.
Clang-format passes for the active sources and API headers; all three object
hashes remain unchanged by formatting in every version.
